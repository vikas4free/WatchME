# WatchME

WatchME is a cinematic movie and TV discovery app built with **React, TypeScript and Vite**, using the supplied **Cinematic Obsidian** design direction (obsidian surfaces, violet/cyan accents, Sora headings and Manrope body text). The UI is responsive for desktop and mobile and the codebase includes starter configuration for Tauri 2 (Windows) and Capacitor (Android).

## What's in the current scaffold

- Cinematic home hero, trending/popular/top-rated rails, movie/series browse pages, title detail modal, cast metadata and search.
- TMDB service layer for trending, popular movies, popular TV, top-rated, multi-search and appended detail data.
- Local watchlist, favorites and viewing-progress storage using Zustand persist.
- A responsive desktop sidebar and mobile navigation drawer.
- Tauri 2 desktop configuration and Capacitor configuration.
- A CineSRC provider adapter that explicitly reports missing integration details instead of inventing stream URLs.

**Important status note:** this is an initial working UI and metadata scaffold, not yet a fully verified streaming product. Playback is intentionally not claimed as working: no CineSRC API/SDK contract was included in the brief. To enable real playback, provide the documented and authorized provider integration details and implement them in `src/services/streaming/provider.ts`. The current Continue Watching area is wired to persisted progress state, but progress is not yet populated by a live video player.

## Requirements

- Node.js 20 or newer and npm
- A TMDB API key for live catalogue data
- For Windows packaging: Rust, the Tauri prerequisites for Windows, and WebView2
- For Android packaging: Android Studio and Android SDK

## Run on the web

1. Clone this repository and enter its folder:
   ```bash
   git clone https://github.com/vikas4free/WatchME.git
   cd WatchME
   ```
2. Install dependencies:
   ```bash
   npm install
   ```
3. Create your environment file. On Windows PowerShell:
   ```powershell
   Copy-Item .env.example .env
   ```
   On macOS/Linux:
   ```bash
   cp .env.example .env
   ```
4. Set `VITE_TMDB_API_KEY` in `.env`, then run:
   ```bash
   npm run dev
   ```

Without a key, the app runs in preview mode with a small sample catalogue. Live TMDB requests require a valid key.

### TMDB credential security

Vite variables prefixed with `VITE_` are included in the client bundle. A TMDB read-only API key is not equivalent to a private server secret, but it is still visible to users if placed here. For production, use a backend proxy, apply rate limits, and do not place private tokens or CineSRC credentials in the frontend or mobile app bundle.

## Windows desktop with Tauri 2

The Tauri configuration is in `src-tauri/`. After installing the Tauri Windows prerequisites:

```bash
npm install
npm run tauri:dev
npm run tauri:build
```

The production bundler is configured for NSIS and MSI targets. Windows installer generation has not been run in this environment; use the commands above on a configured Windows development machine and resolve any platform prerequisite prompts.

## Android with Capacitor

Generate the native Android project and open it in Android Studio:

```bash
npm install
npm run build
npm run android:add
npm run android:sync
npm run android:open
```

In Android Studio, configure signing and build an APK or Android App Bundle for release. Test Android back navigation, screen rotation, background/foreground restoration and video playback on actual devices before release. The native Android project is generated by Capacitor and is not checked in at this scaffold stage.

```
  pages/               # route/page modules (expand as features grow)
  services/
    tmdb/client.ts     # metadata API client
    streaming/         # provider adapter
  store/library.ts     # persisted local library
  styles.css           # responsive cinematic theme
  types/media.ts       # shared media models
src-tauri/             # Tauri 2 desktop shell
capacitor.config.ts    # Capacitor Android configuration
```

## CineSRC integration boundary

The project brief asks to inspect the real CineSRC API or SDK before implementing stream resolution. No verified documentation or credentials were supplied with the UI ZIP, so the current adapter intentionally throws a clear configuration message. Do not substitute guessed endpoints, scraped player URLs, or access-control/DRM bypasses. Connect only a documented integration and content the user is authorized to access.
